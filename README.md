# Markz Net — نظام إدارة حلقات ومسابقات القرآن الكريم (نسخة مستقلة بدون إنترنت)

نسخة مستقلة بالكامل من نظام إدارة المسابقة الرمضانية لحفظ القرآن الكريم،
تعمل **بدون أي إنترنت أو خدمات سحابية**: كل البيانات (الطلاب، المتابعة
الشهرية، المسابقات، الجوائز، الداعمون، المصروفات، الوسائط، الحسابات)
تُخزَّن على الجهاز نفسه.

## الهوية — كيف أفرّق بينه وبين تطبيق «مركز إنماء»؟

هذا التطبيق **منفصل تماماً** عن تطبيق مركز إنماء الأهلي الخيري (النسخة السحابية)،
ويُثبَّت **بجانبه** لا بدلاً منه:

|                  | مركز إنماء الأهلي الخيري (السابق) | Markz Net (هذه النسخة)         |
| ---------------- | --------------------------------- | ------------------------------ |
| معرّف الحزمة     | `org.inmaa.msabkarmdan`           | `net.markz.app`                |
| الاسم على الجهاز | مركز إنماء الأهلي الخيري          | Markz Net                      |
| الأيقونة         | شعار المركز                       | مصحف + سهم + شارة «بلا إنترنت» |
| قاعدة البيانات   | `inmaa_local`                     | `markznet_local`               |
| يحتاج إنترنت     | نعم (سحابة Supabase)              | **لا إطلاقاً**                 |

العلامات الظاهرة داخل هذا التطبيق: وسم **«نسخة بلا إنترنت»** بجانب الاسم في كل ترويسة،
وشارة خضراء «نسخة بلا إنترنت · البيانات على هذا الجهاز» في الشريط الجانبي ورؤوس
الصفحات، وبطاقة تعريف في صفحتي الدخول والإعدادات، وسطر في كل تقرير مطبوع.

تفاصيل كاملة (بما فيها إثبات أن التثبيت لا يمسّ بيانات التطبيق السابق):
[docs/الهوية-وتمييز-النسختين.md](docs/الهوية-وتمييز-النسختين.md)

## المزايا

- واجهة عربية RTL كاملة بنفس تجربة النسخة الأصلية.
- **حسابات متعددة** على نفس الجهاز مع عزل كامل لبيانات كل حساب، وأول حساب
  يُنشأ يصبح مسؤولاً.
- **منح الاطلاع** (قراءة فقط) على بياناتك لمستخدم آخر — مع شريط تنبيه أصفر
  وزر عودة لبياناتك.
- **روابط المعلمين والمعلمات**: رابط خاص بكل معلم/ة لعام/شهر يفتح دون تسجيل
  دخول، وترسيلاته تصل لصفحة «الوارد» للمراجعة والاعتماد، مع «التقرير
  اليدوي» لمن لا يستخدم الجوال.
- **المتابعة الشهرية** كاملة (حفظ جديد + مراجعة + مواظبة وسلوك) مع احتساب
  الأجزاء والمجموع السنوي تلقائياً.
- **سجل المعلمين والمعلمات العام** (مستقل عن الأعوام) بتبويبات: السجل،
  الإكراميات الشهرية والسنوية، المساعدات العينية، وشهادات التقدير — مع
  تغيير الاسم في كل السجلات دفعة واحدة.
- **الأسئلة والاختبارات**: بنك أسئلة لكل عام + مولّد نماذج اختبارات الحفظ من
  نص المصحف الكامل المخزَّن محلياً (`public/quran/uthmani.json`) مع أوراق
  طباعة ومفتاح تصحيح — كله بدون إنترنت.
- **المتأخرات والتنبيهات الذكية**: كشف تلقائي بالمتابعات غير المسجّلة
  والإكراميات غير المحفوظة وتعهّدات الداعمين وبيانات المصروفات الناقصة،
  مع الطباعة والنسخ.
- **أقسام المركز**: قسم المساعدات والرعاية وكفالة الأيتام وقسم التدريب
  والتأهيل — سجل مستفيدين وبرامج محلي بالكامل لكل قسم.
- **ملفات الوسائط** (صور/فيديو) محفوظة محلياً في IndexedDB.
- **استيراد/تصدير Excel** وطباعة/تصدير PDF للكشوفات والتقارير.
- يعمل على المتصفح وعلى أندرويد (تطبيق Capacitor) بهوية بصرية مستقلة وأيقونة خاصة.

## التشغيل السريع

```bash
npm install     # مرة واحدة (ينسخ ملف SQLite/WASM تلقائياً)
npm run dev     # وضع التطوير
```

### نسخة الإنتاج (خادم محلي)

```bash
npm run build   # يبني خادم Node في .output/
npm start       # يشغّله: node .output/server/index.mjs
```

ثم افتح `http://localhost:3000`.

### مشاركة ضمن الشبكة المحلية (LAN)

شغّل الخادم على كل الواجهات وافتحه من أي جهاز في نفس الشبكة عبر عنوان IP
الجهاز:

```bash
HOSTNAME=0.0.0.0 PORT=8080 npm start
# ثم من الجوال: http://<عنوان-IP-للجهاز>:8080
```

**ملاحظة مهمة:** كل متصفح يحتفظ بقاعدة بياناته ووسائطه وجلسته في جهازه
(IndexedDB خاص بالمتصفح). البيانات المُدخلة من جوال آخر تُخزَّن في ذلك
الجوال، لا في الجهاز الذي يشغّل الخادم. للمشاركة الفعلية بين مستخدمين
استخدم نفس المتصفح/الجهاز مع منح الاطلاع، أو تطبيق أندرويد على جهاز واحد.

روابط المعلمين والمعلمات تعمل عبر الشبكة المحلية لأنها تُبنى من عنوان
الصفحة نفسها (`window.location.origin`).

## تطبيق أندرويد

```bash
npm run build
npx cap sync android
cd android && ./gradlew assembleDebug
# الناتج: android/app/build/outputs/apk/debug/app-debug.apk
```

أو ارفع المشروع إلى GitHub وشغّل workflow «بناء تطبيق أندرويد (APK)» —
يبني APK جاهزاً للتحميل دون أي أسرار أو خدمات خارجية. داخل التطبيق تُخزَّن
البيانات في SQLite الأصلية للجهاز.

## الحسابات والصلاحيات

- أول حساب يُنشأ على الجهاز يصبح **مسؤولاً**؛ والمسؤول يضيف بقية الحسابات
  أو يُنشئ روابط تسجيل، ويرقّي من يشاء لمسؤول.
- كلمات المرور تُخزَّن كبصمة PBKDF2 (150 ألف دورة) — لا تُخزَّن أبداً كنص.
- كل جدول بيانات يحمل `user_id` وكل استعلام يُفلتر به؛ حذف قاعدة بيانات
  مستخدم يمسح صفوفه فقط.
- التفاصيل الكاملة في [docs/دليل-نظام-المستخدمين.md](docs/دليل-نظام-المستخدمين.md).

## هوية المركز (اسم وشعار) — لأكثر من مركز

كل حساب يكتب **اسم مركزه** ويرفع **شعاره** من: الإعدادات → **هوية المركز**.

- الاسم والشعار يظهران في الشريط الجانبي وكل ترويسات الصفحات وصفحة الدخول
  وعنوان التبويب، وفي **كل كشوف الطباعة** والشهادات.
- الشعار يُصغَّر تلقائياً (640 بكسل، WebP) ويُخزَّن محلياً مع إعدادات الحساب،
  فلا خروج لأي ملف من الجهاز.
- لكل حساب هويته الخاصة؛ وفي وضع الاطلاع تظهر هوية صاحب البيانات للقراءة فقط،
  وصفحة الدخول تعرض هوية آخر مركز مُعرَّف على الجهاز.
- الدليل الكامل: [docs/هوية-المركز-والتخصيص.md](docs/هوية-المركز-والتخصيص.md).

## القائمة الجانبية (تثبيت من 1280px أو درج يُغلق)

- **من 1280px (`xl`) وأعلى:** القائمة مثبّتة دائماً، ويُحجز لها عرضها (288px)
  في تخطيط الصفحات.
- **أدنى من ذلك (جوال/جهاز لوحي/شاشة متوسطة):** تتحوّل إلى **درج** فوق المحتوى
  يُفتح بزر صغير أعلى يمين الصفحة، و**يُغلق فور اختيار أي صفحة**، أو بمفتاح
  `Esc`، أو بالنقر على الحاجب خارجها، أو بزر الإغلاق داخلها — وهي مخفية
  مُعطَّلة (`inert`) فلا تلتقط التركيز ولا تحجب المحتوى.
- نقطة التثبيت **واحدة** في `src/hooks/useSidebarDock.ts`
  (`SIDEBAR_DOCK_BREAKPOINT = 1280`) يقرأها كل من القائمة والتخطيط، فلا
  يفترقان: القائمة كانت قبل ذلك تُثبَّت من 768px بلا زر إغلاق (الزر العائم كان
  مخفياً عند `md`) فتبقى مفتوحة فوق الصفحة بعد الاختيار.
- اختبار الانحدار: `npm run test:layout` (يفحص المصادر ويركّب القائمة والتخطيط
  فعلياً فوق DOM).

## أين تُخزَّن البيانات؟

| النوع                       | المكان                                            |
| --------------------------- | ------------------------------------------------- |
| كل جداول البيانات والحسابات | قاعدة SQLite واحدة باسم `markznet_local`          |
| ملفات الصور والفيديو        | متجر IndexedDB باسم `markznet_media`              |
| الجلسة (تسجيل الدخول)       | `localStorage` بمفتاح `markznet.session`          |
| هوية المركز لكل حساب        | جدول `settings` بمفتاح `<userId>:center_identity` |
| نسخة الهوية لصفحة الدخول    | `localStorage` بمفتاح `markznet.centerBrand`      |

- على المتصفح: تعمل القاعدة عبر مكوّن jeep-sqlite (محرك sql.js/WASM) وتُحفظ
  داخل IndexedDB تلقائياً (حفظ مؤجَّل ومجمَّع للأداء).
- على أندرويد: SQLite الأصلية للجهاز عبر @capacitor-community/sqlite.

## الاختبارات

```bash
npm run test:db           # قاعدة البيانات المحلية: المخطط + CRUD (sql.js)
npm run test:integration  # تكاملية: مصادقة/صلاحيات/عزل بيانات/بوابة معلمين
npm run test:connection   # انحدار: اعتماد اتصال أصلي موجود (قفلة already exists)
npm run test:layout       # انحدار: تثبيت القائمة من 1280px وإغلاق الدرج عند الاختيار
```

الاختبارات التكاملية تحزّم **الشيفرة الحقيقية** (`storage` + `localAuth` +
`users` + `teacherPortal` + `localDB`) عبر esbuild وتشغّلها في Node فوق
sql.js بنفس المخطط المستخرج من `sqliteClient.ts`، مع ستُبّات لـ
`sqliteClient` و`mediaStore` ومحاكاة `window/localStorage` — فتُغطي:
أول-مسؤول، الدخول وتغيير كلمات المرور، منح/سحب الاطلاع، عزل بيانات
المستخدمين، وضع الاطلاع للقراءة فقط (ReadOnlyViewError)، حذف قاعدة مستخدم
مع بقاء غيره، بوابة المعلمين (إرسال/رفض/تحديث/اعتماد)، التقرير اليدوي،
وهوية المركز (اسم + شعار لكل حساب، نسخة الجهاز، ومنع التعديل في وضع الاطلاع).

`npm run test:layout` يعمل على نفس المبدأ: يحزّم `AppSidebar` والتخطيط المُصدَّق
ويشغّلهما فعلياً فوق DOM (jsdom) — فتح الدرج، اختيار صفحة، `Esc`، الحاجب، زر
الإغلاق، تغيّر المسار، وتغيّر عرض الشاشة — مع فحوص بنيوية تمنع تكرار نقطة
التثبيت أو حجز المساحة (`mr-72`) خارج `useSidebarDock`.

## العمل دون خادم مؤقتاً (Service Worker)

في نسخة الإنتاج يُسجَّل service worker (`public/sw.js`):

- الأصول المُهشَّرة (JS/CSS/خطوط): تُقدَّم من الكاش فوراً مع تحديث خلفي.
- فتح الصفحات: الشبكة أولاً؛ عند تعذّرها آخر نسخة مخزنة للصفحة، وإلا
  صفحة `offline.html` العربية.

بهذا تظل الواجهة تعمل (قراءة للبيانات المحلية) حتى لو انقطع خادم Node
مؤقتاً. لا يتدخل الـ SW في بيانات SQLite/IndexedDB إطلاقاً، ولا يُفعَّل في
وضع التطوير ولا داخل تطبيق أندرويد.

## النسخ الاحتياطي

لا توجد سحابة — النسخة الاحتياطية مسؤوليتك المحلية:

- **نسخة JSON كاملة للحساب** من الإعدادات: 16 جدول بيانات، إعدادات الحساب،
  والوسائط. حسابات الدخول وكلمات المرور وأذونات الاطلاع مستثناة.
- الاستعادة تعرض معاينة ثم تدمج فقط؛ لا تحذف ولا تستبدل البيانات الحالية، وتربط
  صفوف الطالب المطابق بالاسم بمعرّفه المحلي وتمنع تكرار بقية السجلات.
- **تصدير/استيراد Excel** من صفحة سجل الطلاب يظل متاحاً للعمل على سجل الطلاب.
- التفاصيل: [دليل النسخ الاحتياطي والاستعادة](docs/نسخ-احتياطي-واستعادة.md).

## الفروق عن النسخة السحابية (Msabka-app)

- لا Supabase ولا أي اتصال شبكي — الحزم السحابية حُذفت كلياً.
- المزامنة «سحابية» أصبحت no-op؛ لا «تغييرات معلقة» بعد الآن.
- المصادقة عبر جدول `app_users` المحلي بدل Supabase Auth.
- روابط بوابة المعلمين تعمل على الشبكة المحلية بدل الإنترنت.
- المعرفات محلية: الطلاب بتسلسل طبيعي من 1، والبقية UUID.
